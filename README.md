# 🐋 AtTool —— 让 LLM 学会「真·艾特」（AstrBot 艾特工具）

<div align="left" style="width:70%">

> 哼～听说你家 LLM 还在输出 `@张三` 这种纯文本糊弄群友？
> 消息发出去，艾特没触发、提醒没送达，人家根本不知道你在喊他——这能忍？
> 本DS看不下去了，尾巴一甩，把「真·艾特」的魔法棒塞到你 Bot 手里～ 🐳

**一句话简介**：让你的 AstrBot 拥有「真正」艾特群成员的能力。LLM 可以查询群成员列表（昵称/群名片/QQ 号），并在回复中输出 `[at:ID]` 标签，由本插件在消息发出前统一渲染为 QQ 的**真实 At 组件**（会触发提醒的那种，不是 `@` 开头的假把式）。

## 核心能力

### 🎯 search_and_mention：让 LLM 自己找人

LLM 通过 `search_and_mention` 工具按昵称/群名片搜索群成员，工具返回**紧凑结果**（仅含命中成员的群名片/昵称、QQ 号、角色标注，以及可直接使用的 `[at:ID]` 标签），省 Token 不废话——本DS特意调过的，哼～才不是为了让你的 API 账单好看呢。

### 🔍 模糊匹配（`enable_fuzzy_search`，默认开）

开启后支持**子串包含匹配**：搜「柴」能找到「柴郡」，搜「武」能捞到「武藏」。用户说「帮我艾特姓柴的」「艾特一下那个叫武的bot」这类模糊指代，LLM 提取关键词就能命中。关闭后必须完全匹配才放行。

> 💡 小知识：搜索结果会带角色中文标注（群主/管理员/成员），多候选列表也逐条标注角色——「艾特群主」这种角色指代，LLM 能结合角色标注判断该点谁。

### ✨ 真实 At 渲染

LLM 只需在回复正文里放 `[at:ID]` 标签（比如 `[at:10086]`），插件就会把它渲染成真正的 `At` 组件。`[at:ID1][at:ID2]` 连续多个标签？一次艾特一群人，没问题～ 🐳

**艾特当前说话人现已支持真 @（v2.6.3 起）**：模型要艾特"正在跟它说话的人"时，这个 ID 由平台事件自带（不需要模型自述、也无法伪造），只要该成员在本群名单里就会渲染成真实 `At`，不再降级成 `@一串数字`。

### 🔐 ID 可信来源约束（防「编造 QQ 号」被渲染）

**v2.6.1 起**，`[at:ID]` 里的成员 ID 必须来自可信来源才会被渲染成真实艾特；**v2.6.2 起**直连号码还必须是**本群成员**；**v2.6.3 起**补上「当前说话人自己」这一路：

| 可信来源 | 说明 |
| --- | --- |
| **工具确认过的 ID** | `search_and_mention` 唯一命中，或 `select_member_by_index` 选定；记忆 120 秒、按 `(会话, 发起者)` 分槽、容量 500 |
| **当轮用户消息里出现的 QQ 号** | 仅当 `allow_direct_qq_at=true`（默认）：消息里出现 5..12 位 ASCII 数字，**且必须是本群成员名单里的号码**（v2.6.2 起，名单复用 180s 缓存）。仅当轮有效；**名单不可用（私聊 / 拉取失败 / 平台返回空）时一律降级**，不再"查不到就照旧渲染" |
| **当前说话人自己** | v2.6.3 起：ID 由事件自带（`get_sender_id()`），**需同时满足「群聊 + 名单可用 + 发送者在名单内」**才渲染真 `At`；私聊、名单不可用或发送者不在名单内 → 仍降级 |

不在可信集里的载荷 → **降级为纯文本 `@载荷`**（不渲染 At、不写审计），并汇总一条 warning；降级文案**优先用群名片/昵称**，拿不到名字才显示 `@号码`（v2.6.3 起）。这样模型"没调工具就自己编一个 QQ 号"的行为不会变成群里的误艾特；**不存在的号码也不会再让平台拒收整条消息**（详见[排障第六步](#第六步群里只有表情包正文全没了先看是不是平台拒收retcode1200)）。被切碎后跨组件拼合出来的 ID 走同一份判定，不可信同样原位降级。想把口径收到最严？把 `allow_direct_qq_at` 关掉，只信任工具确认过的 ID。

### 🎯 什么时候会触发艾特工具（v2.6.4 起：看意图，不看关键词）

**以前**：注入给模型的说明是一串触发词（「艾特」「@」「at」「叫一下」「喊一下」「呼叫」「叫他/她」…），模型把它读成了"必须出现这些词才调工具"的清单——用户说「艾特一下，我试试看呢。」时反而没调工具，艾特失败。

**现在**（插件每轮自动注入，无需改配置）：

- **要调用工具**：只要用户的意图是让你把某位群成员「**叫出来 / 提醒他 / 让他注意 / 让他回应**」，无论用什么说法，都必须先调用 `search_and_mention` 取得 ID，再输出 `[at:ID]`。正例：「把张三叫出来」「让李四看看这个」「提醒一下王五」「@群主」。
- **不要调用**：**只是顺带提到某人的名字、并不要求他回应**时——「刚才张三说的那件事」「李四昨天做的事挺有意思」「我记得王五提过这个」——不要调工具，也不要输出任何 `[at:ID]` 标签（这条同时挡住"高频误 @"的老毛病回归）。
- **三条边界**：① 要 @ 全体 / 大家 / 所有人 → 按 **@全体权限** 那一节处理，不拿这些词去调工具；② 只说「艾特一下」却**没给对象** → 先反问他是谁，不猜、不调工具；③ 说「别艾特任何人」「不要 @ 他」这类**否定指令** → 绝对不调工具、不输出标签。
- **顺带一提（查询类仍然要查）**：用户只是想**查询**某人的 QQ 号/群名片（不是要他回应）时——**仍然应该调用 `search_and_mention` 去查**，只是**不要在正文里输出 `[at:ID]` 标签**，用文字把查到信息告诉他即可。
  > 注：提示词里目前只写了"不要输出标签"，**没有**写"可以先调用工具去查"，所以"查询类仍应调用工具"这一半**由本文档兜底**（评审 T33 的 N1）。
- 触发词仍列在说明里，但只是**例句**；用户直接给 QQ 号的分支不受影响（仍由 `allow_direct_qq_at` 控制）。

> 与[配置](#配置)里的 `llm_prompt` 关系：面板那段（含旧触发词清单）仍会照常注入、与新段叠加，不冲突；既然意图判定已经由动态段负责，**面板那段可以精简或留空，不影响功能**（属可选项，是否精简由你自己决定）。

### 🛡️ 角色卡约束免疫

角色卡常见的「禁止方括号」「只能纯文本回复」类约束，容易让 LLM 把标签吞掉。本插件对付它的方式是**机制级兜底**：

- 默认提示词内置**红线条款**：禁止把工具返回的原始文本直接发给用户、禁止描述工具调用过程（「让我查查」「找到了」都不行）、禁止捏造用户 ID；
- 即使 LLM 真的因为角色卡约束省略了标签，**兜底补插**机制也会在整轮渲染时按「唯一命中」自动补回 `[at:ID]`——艾特照样不丢。

（本DS才不是在夸这个设计有多妙，只是……哼，你们用就完事了。）

### 🧊 延迟渲染 + send 兜底：双保险

- **延迟渲染**：`[at:ID]` 以纯文本形式贯穿所有中间插件（第三方插件随便重建消息链，只要保留文本就没事），由本插件在 `on_decorating_result`（priority=-1000，实测**早于**分段插件的 -1e17）统一渲染为 At 组件——先渲染、后分段，标签不会被分段切走；
- **send 兜底**：万一有插件清空消息链后直接 `event.send()` 裸文本？本插件在请求阶段就给事件实例装上了 send 包装，消息真正发往平台**前一刻**再渲染一次链内已有的标签。

两条路径共用同一渲染流水线。**v2.6.0 起 send 兜底只渲染链内已有的标签，绝不补插、绝不消费兜底缓存、绝不剥离其他段的标签**——逐段发送时不再改写分段结果（旧实现会把 At 补到第一段、或把后续段的真实标签当"重复"剥离）。补插只发生在主钩子（整轮渲染）这一处。

### 🧩 跨组件碎片恢复

标签被切碎了？照样给你拼回来：

- 相邻 Plain 组件先自动合并（`[at:12` + `345]` 分处两段？合并后完整匹配）；
- 跨组件切碎（前缀和闭合括号分处不同组件、**中间隔着 At 组件**）→ 跨组件拼合，原位恢复；
- **零宽字符污染**（`\u200b` 混进标签里）→ 零宽视为透明，清洗后重新暴露完整标签，恢复渲染。

### 🩹 残缺标签容错

恢复不了的残缺标签按形态分别处理，**绝不把标签语法留在交付文本里、也绝不误删你的正文**：

- 载荷无法解析（`[at:柴郡]`、`[at:ID]`、`[at:１２３]`、超长数字）→ 降级为可读纯文本 `@载荷`，并打 warning；
- 空载荷（`[at:]`、`[at: ]`）→ 删除标签语法；
- 未闭合（整条链里始终没有 `]`，如 `[at: 123`）→ 删除 `[at:` 语法片段、保留其余正文（`123`），并打 warning；
- 收尾后正文里若仍有标签语法残留（一般是被第三方插件在分段/重建时切断）→ 记一条 warning 便于排查。

完整形态对照表见[标签形态与降级规则](#标签形态与降级规则)。

### 👥 多目标艾特

`[at:ID1][at:ID2][at:ID3]`——LLM 可以在一条回复里艾特多人，插件逐个渲染，一个都不少。

### 📢 @全体（权限验证 + 冷却）

- 输出 `[at:all]` 即可触发 @全体；
- `permission_verification`（默认开）：仅**群主、管理员或 Bot 超级管理员**可以触发，普通成员要求 @全体时 LLM 会被明确告知无权限并改用自然语言说明；
- `at_all_cooldown`（默认 60 秒）：同一群两次 @全体 的最小间隔，冷却内的第二次会被自动**降级为纯文本「@全体成员」**，并向操作者反馈受限原因（冷却中，剩余约 X 秒）。

### 🔒 会话白名单 / 黑名单

- `session_whitelist`：仅允许列表内的会话使用艾特（条目可为完整 UMO，用 `/sid` 获取；或直接填群号）；留空 = 全部允许；
- `session_blacklist`：禁止列表内的会话使用；**黑名单优先级高于白名单**；
- 命中禁止会话时，`[at:ID]` 会被剥离、`[at:all]` 降级为纯文本「@全体成员」、非数字载荷转纯文本 `@载荷`（大小写 / 全角 / 带空格形态同样处理）。

### 🪄 兜底补插（LLM 漏标签也不怕）

`search_and_mention` **唯一命中**成员时写入会话级兜底缓存（TTL 120 秒）；若 LLM 最终回复里没有携带任何 `[at:ID]` 标签，插件会在整轮渲染时自动补插标签完成艾特。关键设计：

- **仅由主钩子消费**（整轮渲染的唯一补插入口），send 兜底路径绝不补插——多段直发时每段各补一次导致**重复艾特**？不存在的；
- 缓存**一次性消费**，读取即删除，跨轮次误用？不存在的；
- 回复中已有其他来源插入的 At 组件时自动放弃补插，绝不重复艾特。

### 📋 审计日志（`enable_audit_log`，默认开）

每次生效的艾特（@单人逐条 / @全体放行 / @全体被拦截）都会落盘一条 JSONL 审计记录到插件数据目录的 `data/plugin_data/astrbot_plugin_AtTool/audit/at_audit_YYYYMMDD.jsonl`（按日切割），字段包含：时间、群号、操作者、操作类型（`at_member`/`at_all`）、目标、是否放行、原因。谁艾特了谁、被没被拦，一目了然——本DS可不喜欢背黑锅，哼～

> 注意：审计记录写在**渲染阶段**，模型没输出标签、或标签被降级/剥离时不会有记录——"没有审计行"不等于"用户没有艾特意图"（那类情况看[排障](#排障)里的告警日志）。

## 标签形态与降级规则

LLM（以及宿主序列化进历史上下文的内容）会写出各种形态的艾特标签。**v2.6.0 起**下列形态全部被接受——大小写、半角/全角冒号、冒号两侧的空白与零宽字符都会先归一：

| 输入形态 | 处理结果 |
| --- | --- |
| `[at:123]` `[At:123]` `[AT:123]` `[aT:123]` | → 真实 At 组件（`At(qq="123")`） |
| `[at: 123]` `[at：123]` `[at : 123]` | → `At(qq="123")`（冒号两侧空白、全角冒号） |
| `[at<零宽>:123]` `[<零宽>at:123]` `[at:12<零宽>3]` `[at:<零宽>123]` | → `At(qq="123")`（零宽字符视为透明） |
| `[at:all]` `[At:All]` | → 走 @全体 权限 + 冷却判定（放行 = 真实 @全体；拦截 = 纯文本「@全体成员」） |
| `[at:柴郡]` `[at:ID]` `[at:１２３]` | → 降级纯文本 `@柴郡` / `@ID` / `@１２３` + warning（**不**产生 At） |
| `[at:1234567890123]`（超过 12 位数字） | → 降级纯文本 `@1234567890123` + warning |
| `[at:1234567890]`（**未经工具确认**，且当轮消息里没有这个号） | → 降级纯文本 `@1234567890` + warning（**v2.6.1 起**，见[ID 可信来源约束](#-id-可信来源约束防编造-qq-号被渲染)） |
| `[at:1234567890]`（当轮消息里出现过该号，但**不是本群成员**） | → 降级纯文本 `@1234567890` + 告警（**v2.6.2 起**；此前会渲染 `At` 而被平台以 `1200` 拒收整条消息） |
| `[at:1234567890]`（工具刚命中过，或当轮消息里出现且**是**本群成员） | → `At(qq="1234567890")`（可信来源） |
| `[at:]` `[at: ]` | → 删除标签语法 |
| `[at:123`（始终没有 `]`） | → 删除 `[at:` 语法片段、保留其余正文 + warning |
| `[at 123]` `[at]` `[avatar:1]` | → 普通文本，原样保留（**不是**标签） |

规则小结：

- **只有 1..12 位 ASCII 数字或 `all` 才会变成真实艾特**；其它载荷一律降级为可读文本，不会出现"艾特到不存在的人"或"非法 QQ 号"；
- **v2.6.1 起，数字载荷还要过[ID 可信来源约束](#-id-可信来源约束防编造-qq-号被渲染)**：只认"工具确认过的 ID"或"当轮用户消息里出现过的 QQ 号"，其余降级为 `@载荷`（防模型编造号被渲染成真实艾特）；
- **v2.6.2 起，直连号码还必须是本群成员**：不在成员名单里的号降级为 `@号码`（名单不可用时一律降级）——因为给非成员号构造 `At` 会被平台 `retcode=1200` **拒收整条消息**；工具路径返回的 ID 不受影响；
- 被切碎的标签会先尝试拼合恢复：相邻 Plain 合并、跨组件拼合（前缀与 `]` 分处不同组件、中间隔着 At 组件）、多处零宽污染循环恢复（单链上限 8 轮）；
- 禁止艾特的会话（`session_blacklist`，或不在 `session_whitelist`）按同一套规则处理：成员标签剥离、`[at:all]` 转纯文本「@全体成员」、非数字载荷转 `@载荷`；
- 宿主会把可整数化的载荷归一（`[at:0123]` 交付时是 `At(qq=123)`），插件不再额外处理前导零，也不做"名字 → 成员"的猜测。

## v2.6.4 修复了什么

**只改提示词，不改渲染**——本版把「什么时候该调用艾特工具」的判定从**关键词清单**换成**意图判定**（完整清单见 [CHANGELOG.md](CHANGELOG.md)）：

1. **现象**：模型只有在自然语言里出现「艾特 / 叫一下 / 找一下」这类词时才调工具；用户说「艾特一下，我试试看呢。」时直接写标签、没调工具，艾特失败；
2. **改法**：意图是「把某人叫出来 / 提醒他 / 让他注意 / 让他回应」就**必须**先调用 `search_and_mention`（无论用什么说法）；触发词降级为**例句**，并写明**反例**（只是顺带提到名字 → 不调工具、不输出标签，顺带挡住"高频误 @"回归）；
3. **四条边界**：@全体/大家 走 @全体权限 那一节；只说「艾特一下」没给对象 → 先反问不猜不调；「别艾特任何人」这类否定指令 → 绝对不调不输出；**查询某人的 QQ 号/群名片 → 仍应调用工具去查，但不要在正文里输出 `[at:ID]` 标签**（这半句由本文档兜底，提示词原文未含）；
4. **明确不变**：渲染、可信来源、成员校验、降级、审计全部保持原样；未改 `_conf_schema.json`、工具名、docstring 与用户已保存的 `llm_prompt`；
5. **工程**：测试 525 → 549 passed；ruff 53 / 83（基线 63 / 91），未新增违规码。

详见[核心能力 → 什么时候会触发艾特工具](#-什么时候会触发艾特工具v264-起看意图不看关键词)。

## v2.6.3 修复了什么

线上反馈「机器人莫名 @ 了我一串数字，还不是昵称」。定位结果：模型**没调用工具**，直接写了 `[at:<当前说话人的 QQ>]`，被 v2.6.1 的可信来源约束降级成了纯文本 `@<号码>`（不是误艾特，但体验不合格）。本版本收口如下（完整清单见 [CHANGELOG.md](CHANGELOG.md)）：

1. **自目标窄例外**：模型要艾特的 ID 若正是当前说话人自己（ID 由平台事件自带、无法伪造），在「群聊 + 名单可用 + 发送者在名单内」时渲染真 `At`；三个条件缺一即沿用 fail-closed 降级；私聊不启用；
2. **降级不再露裸号码**：优先显示群名片/昵称，拿不到名字才回退 `@号码`；成员名字本身含 `[at:…]` 语法时丢弃该名字（防止降级文案把标签原文带进群）；
3. **动态提示词补强**：新增「艾特当前说话人也必须先调用工具」，同时与「QQ号处理」小节保持一致（用户直接给号且开关开启时仍可直接用）；
4. **工程**：测试 484 → 525 passed；ruff 53 / 83（基线 63 / 91），未新增违规码；未新增配置开关与依赖，`_conf_schema.json` 未改动。

## v2.6.2 修复了什么

v2.6.1 之后，第三组线上用例暴露了一个更"致命"的连锁反应：**用户给出一个不存在/非本群的 QQ 号 → 插件照常渲染 `At` → 平台以 `retcode=1200 Get Uid Error` 拒绝整条消息 → 正文全丢，群里只剩一张表情包**。本版本把它堵住（完整清单见 [CHANGELOG.md](CHANGELOG.md)）：

1. **直连号码必须先过本群成员名单**：`allow_direct_qq_at=true` 时，当轮消息里的 5..12 位数字要先与本群成员名单（复用既有 `get_group_member_list` 与 180s 缓存）取交集，**只有本群成员号**才会渲染 `At`；不在名单里的降级为 `@<号码>` 文本，消息照常发出；
2. **名单不可用时一律降级（fail-closed）**：私聊、名单拉取失败、平台返回空名单 ⇒ 直连号码一律降级（此前是"查不到就照旧渲染"，实测照样被平台 `1200` 拒收整条消息）；工具路径（`search_and_mention` / `select_member_by_index`）不受影响；
3. **两类告警文案可区分**：`已按未知来源降级（不渲染 At）`（名单不可用）vs `未经工具确认、或不在本群成员名单`（名单里没有该号），便于排障定位；
4. **工程**：测试 462 → 484 passed；ruff 53 / 82（基线 63 / 91），未新增违规码；未新增配置开关与依赖，`_conf_schema.json` 未改动。

排障与已知限制见[排障第六步](#第六步群里只有表情包正文全没了先看是不是平台拒收retcode1200)与[已知限制](#已知限制)。

## v2.6.1 修复了什么

v2.6.0 上线后真实群实测暴露两个问题：模型**没调工具却自己编了一个 QQ 号**写成 `[at:<编造号>]`，被渲染成了真实艾特（误艾特一次）；同时查明上游 `meme_manager` 会在这类标签到达本插件前把它们吞掉。本版本收口如下（完整清单见 [CHANGELOG.md](CHANGELOG.md)）：

1. **编造 ID 不再渲染**：`[at:ID]` 的成员 ID 必须来自可信来源——工具确认过的 ID（120s 内、按 `(会话, 发起者)` 分槽），或（`allow_direct_qq_at=true` 时）**当轮用户消息里出现的 QQ 号**；其余一律降级为纯文本 `@载荷` + warning，不渲染 At、不写审计。详见[ID 可信来源约束](#-id-可信来源约束防编造-qq-号被渲染)；
2. **无用户上下文时 fail-closed**：取不到用户上下文时只信任"工具确认过的 ID"，不再有"无上下文即放行"的旁路；
3. **跨组件拼合路径并入同一判定**：被切碎后拼合出的 ID 走同一份可信集，不可信原位降级（不渲染、也不静默删除）；
4. **可信 ID 记忆按发起者分槽**：同群他人一次工具命中不再覆盖你的记录（此前会造成"你的合法艾特被降级 + 兜底补插被拦"的漏艾特）；
5. **排障补强**：把「上游吞标签」（见[排障第四步](#第四步回复里的-atid-在群里凭空消失先查上游插件)）与「改配置必须重载/重启」（见[排障第五步](#第五步改了配置却不生效必须重载重启)）写进文档；
6. **工程**：测试 412 → 461 passed（+1 xpassed，转正用例，可见不计失败）；ruff 53 / 82（基线 63 / 91），未新增违规码；未新增配置开关与依赖，`_conf_schema.json` 未改动。

## v2.6.0 修复了什么

## 配置

安装后**开箱即用**，无需任何配置即可使用全部核心功能。以下配置项在 AstrBot 插件管理面板中调整：

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `permission_verification` | bool | `true` | @全体 权限验证。开启后仅群主、管理员或 Bot 超级管理员可触发 @全体 |
| `allow_direct_qq_at` | bool | `true` | 允许直接使用 QQ 号艾特。开启后：用户当轮消息里出现的 QQ 号（5..12 位）**且必须是本群成员**才可被渲染（v2.6.2 起，名单不可用时一律降级）；关闭后：只信任工具确认过的 ID（必须走 `search_and_mention`）——**关掉它是不受任何名单/网络因素影响的最严一档** |
| `enable_fuzzy_search` | bool | `true` | 模糊昵称搜索。开启后支持子串部分匹配（搜「张」可找到「张三」）；关闭后必须完全匹配 |
| `session_whitelist` | list | `[]` | 会话白名单。条目可为完整 UMO（用 `/sid` 获取）或群号；留空表示允许全部会话 |
| `session_blacklist` | list | `[]` | 会话黑名单。格式同白名单；黑名单优先级高于白名单 |
| `llm_prompt` | text | 内置默认 | LLM 自定义提示词基底（艾特格式说明 + 红线条款），Markdown 编辑。**v2.6.4 起**：触发判定已由插件动态注入的意图规则负责，这项**可精简或留空、不影响功能**（留空也不会关闭意图规则）；是否精简由你决定 |
| `at_all_cooldown` | int | `60` | @全体 冷却秒数。0 = 不限制；冷却内第二次 @全体 自动降级纯文本并反馈原因 |
| `enable_audit_log` | bool | `true` | 艾特操作审计日志。落盘到插件数据目录 `audit/at_audit_YYYYMMDD.jsonl`（JSONL，按日切割） |
| `member_list_cache_ttl` | int | `180` | 群成员列表缓存秒数。千人级大群搜索时复用列表、减少全量拉取；0 = 不缓存 |
| `member_aliases` | list | `[]` | 成员别名映射（搜索兜底）。兼容 `{"才俊": "柴郡"}` 字典与 `["才俊=柴郡"]` 列表两种写法；真名/群名片精确与模糊均未命中时，按别名展开再搜一次 |

> **v2.6.0 / v2.6.1 均未新增配置项**（`_conf_schema.json` 无改动），旧配置无需迁移；两个版本的日志与降级行为都由既有配置控制。

## 使用示例

装完即用，在群聊里直接跟 Bot 说就行～

### 场景 1：单目标艾特

> **用户**：@Bot 帮我艾特一下张三，喊他上线打游戏。
>
> **Bot（后台动作）**：
> 1. 调用 `search_and_mention(name="张三")` 查询群成员；
> 2. 唯一命中「张三（10086，成员）」，得到标签 `[at:10086]`；
> 3. 把标签放进回复正文，最终由插件渲染为真实 At 组件。
>
> **Bot（实际回复）**：@张三 喊他上线打游戏。

### 场景 2：模糊/角色指代

> **用户**：@Bot 帮我艾特一下姓柴的。
>
> **Bot（后台动作）**：
> 1. 提取搜索关键词「柴」，调用 `search_and_mention(name="柴")`；
> 2. 模糊匹配命中唯一成员「柴郡（1024，管理员）」→ `[at:1024]`。
>
> **Bot（实际回复）**：@柴郡 收工了，来冒个泡～

> **用户**：@Bot 艾特一下群主。
>
> **Bot（后台动作）**：搜索并结合结果中的角色标注（群主/管理员/成员）判断目标；若搜索词命中多个候选，会列出带角色标注的编号列表请用户确认。

### 场景 3：多目标艾特

> **用户**：@Bot 艾特一下武藏和长风，说今晚开黑。
>
> **Bot（后台动作）**：依次搜索两人，得到 `[at:20001][at:20002]`，一条回复渲染出两个真实 At。
>
> **Bot（实际回复）**：@武藏 @长风 今晚八点开黑，别迟到～

### 场景 4：多候选确认

> **用户**：@Bot 艾特张伟。
>
> **Bot（后台动作）**：搜「张伟」命中 3 个候选（带序号 + 角色），请用户选择；用户回复序号后调用 `select_member_by_index` 获取最终标签（候选记录 120 秒内有效，过期需重新搜索）。

### 场景 5：@全体

> **用户**：@Bot 艾特全体成员，通知明天维护。
>
> **Bot（后台动作）**：输出 `[at:all]` → 插件校验操作者权限（群主/管理员/超管）+ 冷却（默认 60 秒）→ 放行则渲染真实 @全体，拦截则降级纯文本「@全体成员」并反馈原因。

## 工作原理

```
LLM 请求阶段
  └─ on_llm_request：注入格式指令 + 红线条款 + @全体权限提示
      └─ 同时给事件实例安装 send 兜底渲染包装（幂等，只装一次）

LLM 调用工具
  └─ search_and_mention / select_member_by_index → 拿到 [at:ID] 标签
      └─ 唯一命中时写入会话级兜底缓存（TTL 120s）

结果阶段（分段插件之前：priority=-1000，早于 splitter 的 -1e17）
  └─ on_decorating_result
      ① 合并相邻 Plain + 跨组件拼合（标签被拆到相邻/分散组件 → 先拼回来）
      ② 无标签？→ 兜底补插（仅此路径消费缓存，一次性）
      ③ 会话准入（白/黑名单，禁止则剥离标签 / 降级 @全体 / 非数字载荷转 @载荷）
      ④ @全体 权限 + 冷却判定
      ⑤ [at:ID] / [at:all] → 渲染为真实 At 组件
      ⑥ 审计落盘（JSONL 按日切割，同事件同目标只记一条）
      ⑦ 收尾：零宽清理 / 空组件剔除 / 相邻合并 / 未闭合语法删除 / 残留告警

发送前一刻（兜底）
  └─ 第三方插件清链直发？→ send 包装再渲染一次（只渲染已有标签，绝不补插）
```

一句话：**标签以纯文本活到渲染钩子，渲染在主钩子与发送前一刻各做一次（同一流水线），补插只认主钩子**。哼～这下你们总该放心了吧？

## 兼容性与注意事项

1. **平台限制**：本插件依赖 aiocqhttp 平台（OneBot V11 协议，如 NapCat 等），**仅支持 QQ 平台**；
2. **群聊限制**：获取群成员列表功能仅在群聊环境中有效，私聊无法使用；
3. **权限要求**：Bot 账号需要有获取群成员列表的权限（通常默认都有）；
4. **AstrBot 版本**：要求 **AstrBot >= 4.26.0**；
5. **角色卡冲突**：若角色卡明确「禁止方括号」等约束，LLM 可能省略标签——本插件的兜底补插机制会尽量补救（详见[角色卡约束免疫](#角色卡约束免疫)），但建议在角色卡中为本插件标签留出余地；
6. **版本号**：本 fork 版本为 **v2.6.4**，`metadata.yaml` 中 `astrbot_version: ">=4.26.0"`；
7. **会话人设的「工具」白名单**：若白名单未勾选 `search_and_mention` / `select_member_by_index`，AI 拿不到艾特工具——这是「需要艾特时 AI 不调用工具」的决定性原因，必须由运维在面板侧处理，见[排障](#排障)；
8. **配置改完要重启/重载**：人设工具白名单与插件配置都不会热重载，见[排障第五步](#第五步改了配置却不生效必须重载重启)；
9. **上游 `meme_manager` 的 `[...]` 吞标签**：其 `on_llm_response` 在 `enable_alternative ∧ remove_invalid_alternative` 同时开启时会吞掉任意 `[...]` token（不只是艾特标签），处置见[排障第四步](#第四步回复里的-atid-在群里凭空消失先查上游插件)；
10. **非本群号码无法真艾特（平台限制）**：v2.6.2 起直连号码必须过本群成员名单，不在名单内只以 `@<号码>` 文本呈现（名单不可用时一并降级），见[排障第六步](#第六步群里只有表情包正文全没了先看是不是平台拒收retcode1200)与[已知限制](#已知限制)第 14–29 条。

## 与分段插件（splitter）共存

分段插件会把一条回复拆成多段投递，艾特组件归到哪一段由它的 `at_strategy` 决定。**本部署实测配置为 `at_strategy = 跟随下段`**（`data/config/astrbot_plugin_splitter_config.json` → `reply_media_settings.at_strategy`），推荐保持该值（`嵌入` 亦可）。原因：

- 钩子执行顺序实测为：`priority=0` 的普通钩子 → **本插件（-1000）** → **分段插件（-1e17）**（AstrBot 按 `-priority` 降序执行）。也就是**本插件先把整条链里的标签渲染成 At，分段插件再对渲染后的链分段**——"跟随下段"会把 At 交到紧随其后的那一段，艾特不会丢在中间；
- v2.6.0 起本插件的 send 兜底渲染**不再改写分段结果**（不补插、不剥离），所以分段插件逐段 `event.send` 也是安全的；
- 分段插件分段后走的是 `context.send_message` 直发（**不经过** `event.send`），本插件的 send 包装看不到这条消息——此时能否艾特，仍由"标签在分段前已渲染成 At"保证，也就是上面的执行顺序。

**建议**：① 保持 `at_strategy = 跟随下段`（或 `嵌入`）；② 不要把标签当作"要清理的文本"——若你在分段插件里配了清理正则/清理词，请避开 `[at:...]` 形态；③ 让分段插件把回复正文里的标签原样保留（本插件的延迟渲染依赖纯文本标签活到 `on_decorating_result`）。

**已知边界**：若有插件在 **priority 高于 -1000** 的阶段清空消息链并直接发送，本插件的主钩子会看到空链（无法补插），且那条直发消息不经过本插件的 send 包装——该场景下不承诺补插（本版本非目标）。

> 附：本版本对分段插件只做了注册表顺序核对与按其源码建模的投递语义验证，**没有真跑它的 `on_decorating_result`**；若它改了 `at_strategy` 或改走 `event.send` 直发，请重跑一次真机复测。

## 排障

### 第一步：确认会话人设的「工具」白名单（最常见原因）

**用户要求艾特、AI 却不调用工具，决定性原因通常不在插件、而在配置**：AstrBot 在会话人设里配置「工具」白名单时，只会把白名单内的工具交给模型；若白名单里没有 `search_and_mention`（和 `select_member_by_index`），模型**根本拿不到**这个工具——插件无法在代码侧补回（只能注入降级提示 + 告警）。

> **运维提示（不是"已修复"）**：面板 → 人设（或该会话绑定的配置）→ 工具 → 勾选 `search_and_mention` / `select_member_by_index`；或把该会话人设切到已放行的「ds娘」。改完后在真实群里让 Bot 艾特一次做复测。
>
> 本版本只在插件侧做了两件事：工具不可达时注入降级提示（不让模型去调用一个不存在的工具）+ 打一条一次性告警。该问题**未在真实群验证为已修复**（沙箱里没有真实 QQ 消息轨迹），请以真实群复测为准。

### 第二步：看日志区分类别

| 现象 | 日志线索 | 说明 |
| --- | --- | --- |
| 群里出现 `[at:...]` 原文 | `标签载荷无法解析（…），已降级为纯文本` / `检测到未闭合的 [at: 标签语法` / `检测到 [at: 标签语法残留` | 载荷本身非法，或标签被第三方插件在分段/重建时切断 |
| 要求艾特但没艾特 | `本轮请求工具集不含 search_and_mention（会话 …），已注入降级提示；当前可用工具: …` | **人设工具白名单没勾选**（每会话只报一次） |
| 同上，但没有上面那条 | `艾特意图未被满足：本轮未调用 search_and_mention，最终回复也无艾特标签` | 提示词已注入且工具可用 → 是模型自己没调工具（每会话只报一次） |
| 同上 | `检测到艾特意图，已注入艾特指令`（info） | 只证明提示词注入成功，不代表模型会调用 |
| 该艾特的人没被艾特 | `兜底补插 [at:…]：LLM 回复未携带艾特标签` | 模型漏了标签，插件按唯一命中补插了一次 |
| 搜不到人 | `search_and_mention 未命中: 关键词=「…」（包含/完全匹配，会话 …）` | 关键词不匹配；可在 `member_aliases` 里补别名 |

### 第三步：查审计日志

- 路径：`data/plugin_data/astrbot_plugin_AtTool/audit/at_audit_YYYYMMDD.jsonl`（按日切割，`enable_audit_log` 控制开关）；
- 字段：`time` / `group_id` / `operator_id` / `op_type`（`at_member` / `at_all`）/ `target_id` / `allowed` / `reason`；
- 用途：确认"这次艾特有没有放行、被谁触发、为什么被拦"。注意：审计只覆盖**成功渲染**的艾特（含 @全体 被拦截的那一条），模型没输出标签时不会有记录。

### 第四步：回复里的 `[at:ID]` 在群里凭空消失？先查上游插件

**症状**：模型回复里明明写了标签（日志/上下文里能看到 `[at:1234567890]`），群里发出来却是"标签不见了、原地留下一个空格"——例如 `好的，这就帮你艾特 [at:1234567890] ` 到群里变成 `好的，这就帮你艾特  `；而且 `enable_audit_log` 开的也不会有任何审计行。

**机制（本机真实复现）**：上游 **`meme_manager`** 在 **`on_llm_response`（priority=99999）**阶段、也就是消息链构建之前，用 `MemeParser` 改写 `response.completion_text`。当它的 `generation.markup.enable_alternative=true` **且** `generation.markup.remove_invalid_alternative=true` 时，**任意 `[...]` token** 都会被当作"无效的表情标记"整段吃掉——`[at:1234567890]`、`[at:all]`、甚至与艾特无关的 `[avatar:1]`、`[at 123]` 都一样。所以这是**上游行为，不是本插件的缺陷**，但它会让"标签走文本"这条路在上游开关打开时失效。为什么"有时吞、有时不吞"？因为要同时满足 `enable_alternative ∧ remove_invalid_alternative`，再加一条上游的作用域门控——三者任一变化就会变。

**处置（照做即可）**：把 meme_manager 的 `generation.markup.remove_invalid_alternative` 关掉（`generation.markup.enable_alternative` 关掉同样有效）。**本机已关**（当前实测 `remove_invalid_alternative=false`）。它另一条 `on_decorating_result` 钩子不吃标签，不用管。

**补充**：如果模型**调用了** `search_and_mention`（唯一命中写入了兜底缓存），即使标签已经被上游吞掉，本插件的**兜底补插**仍会把艾特救回来（这一路有审计行）——所以"模型不调工具 + 上游吞标签"才是最坏组合。

### 第五步：改了配置却不生效？必须重载/重启

**运行中的服务不会自动重读配置**。修改人设的「工具」白名单、或任何插件配置后，必须**重载插件或重启 AstrBot** 才会生效。

本机就踩过一次：上一次重启发生在 19:37，而人设配置的写入时间是 19:40 ⇒ 白改一轮，直到 20:44 再次重启才读到。

**核查"当前实例跑的是哪份代码"**：比较进程启动时间与文件 mtime——

```bash
ps -o pid,lstart,cmd -p <AstrBot 的 python 进程 PID>   # 进程启动时间
stat -c '%y %n' data/plugins/astrbot_plugin_AtTool/main.py   # 代码落盘时间
```

`main.py`（或配置文件）的 mtime **晚于**进程启动时间，说明当前实例加载的是旧代码/旧配置，改动尚未生效（写这份文档时就是这种情况：实例 21:43:12 启动，`main.py` 22:37:17 落盘）。

### 一条成功链路的留痕长什么样

正常的"工具调用 → 渲染 → 审计"完整链路是这样留痕的，可用于对照排障：

1. **工具命中日志**：`[AtTool] search_and_mention 命中: <昵称> (<QQ>，<角色>，会话 <UMO>)`；
2. **兜底缓存**：唯一命中时写入会话级缓存（120s，仅在模型漏标签时才会用到）；
3. **交付**：群里出现真实艾特（不是 `@名字` 纯文本）；
4. **审计行**：`data/plugin_data/astrbot_plugin_AtTool/audit/at_audit_YYYYMMDD.jsonl` 当日文件新增一行，形如
   ```json
   {"time": "2026-10-05T20:46:12", "group_id": "<群号>", "operator_id": "<操作者 QQ>", "op_type": "at_member", "target_id": "<被艾特 QQ>", "allowed": true, "reason": "ok"}
   ```
   （本机实测：2026-10-05 20:46 出现这样一条 `at_member` 放行记录。）

对照结论：**有审计行 = 渲染成功；有 warning 无审计 = 可信校验拒绝（多半是编造 ID）；两者都没有 = 标签在到达本插件前就不见了（见第四步）或模型没写标签**。

### 第六步：群里只有表情包、正文全没了？先看是不是平台拒收（retcode=1200）

**症状**：Bot 那条回复的**正文、文字、艾特全部消失**，群里只看到紧随其后的一张表情包（或什么都没有），像是"Bot 没说话"；而审计文件里**却是有一行允许记录**。

**机制（线上实测）**：平台（NapCat / OneBot）对**无法解析的 QQ 号**会返回 `retcode=1200 Get Uid Error`，并且**拒绝整条消息**——不是只跳过那一个 `At` 段。日志特征：

```
[Core] [ERRO] [respond.stage:322]: Failed to send the message chain: ... 
error = <ActionFailed status='failed', retcode=1200, message='Get Uid Error'>
```

线上实例：用户给了一个不存在/非本群的号码，模型照抄成 `[at:<号码>]`，插件渲染成真实 `At` 后整条被拒。

**处置（v2.6.2 起自动处理）**：直连号码必须先过**本群成员名单**，不在名单内降级为 `@<号码>` 文本（消息照常送达）；名单不可用（私聊 / 拉取失败 / 平台返回空）时**一律降级**，不再冒险渲染。所以升到 v2.6.2 后这种整条丢失不会再由本插件触发。

**若仍看到 `retcode=1200` 或日志长期出现"无法获取群成员名单"**：检查适配器 `get_group_member_list` 的**权限**、**大群名单截断**与网络；必要时让 AI 先做一次成员搜索（`search_and_mention`）刷新名单（180s 缓存）。

**注意审计语义**：审计行表示"**插件渲染放行**"，**不等于平台投递成功**——线上 `2026-10-05T22:02:34` 就有一行 `target_id=<号码> / allowed: true`，而那条消息实际被平台 `1200` 拒收（正文全丢）。判断"是否真的发出去了"，以平台侧结果为准。

### 第七步：机器人为什么会 @ 出一串数字？

> ⚠️ **先记住一点**：`@1234567890` 这种**是纯文本**，不是真艾特——QQ 里看起来像 `@`，但它**不会触发提醒、也不是 `At` 组件**；插件日志与审计能证明这一点（降级路径**不写** `at_member` 审计）。群友可能会把它误看成"真艾特"，其实只是可读的降级文案。

**症状**：群里出现 `@1234567890` 这样**一串纯数字**（不是昵称，也不是真艾特）；说话人往往就是发这句话的人。

**判据（journald / 插件日志）**：

```
[AtTool] WARN 检测到未经工具确认、或不在本群成员名单的艾特 ID（疑似编造/上游残留），已降级为纯文本 @…
```

看到这条就说明：模型**没有调用** `search_and_mention`，而是直接从上下文里抄了一个号码写成 `[at:号码]`；v2.6.1 起的[ID 可信来源约束](#-id-可信来源约束防编造-qq-号被渲染)判定它不可信，于是把它降级成了纯文本。

**处置**：

- **正常现象**：这不是误艾特（没有渲染成真 `At`、不会触发提醒），而是安全约束在生效——可以观察它**是否频繁出现**；
- **v2.6.3 起体验已改善**：① 若那个号码正是**当前说话人自己**，且本群名单可用、他在名单里，现在会渲染成**真 `At`**；② 其他降级文案会**优先显示群名片/昵称**，拿不到名字才显示 `@号码`；
- **想少见到它**：确保该会话人设的「工具」白名单勾选了 `search_and_mention`（见[排障第一步](#第一步确认会话人设的工具白名单最常见原因)）——模型拿得到工具才会走工具。

## 已知限制

> 以下为**未修复 / 未验证 / 残余风险**项，v2.6.2 不做承诺；写在这里是为了让运维判断有正确前提。

1. **会话人设工具白名单（配置层，反馈①的真根因）**：见[排障](#排障)——插件侧只做了降级提示与告警，真正的动作在面板勾选；勾选之前，"需要艾特时 AI 不调用工具"仍会复现。
2. **流式跨 chunk 标签**：同一标签被切成 `chunk1='前缀[at:12'` / `chunk2='3] 后缀'` 时，第一个 chunk 的交付文本会保留标签语法（仅单个 chunk 内完整时才渲染）。**主群路由档案（`abconf_596ffb44`）实测 `streaming_response=false` + `unsupported_streaming_strategy=realtime_segmenting`，不进流式分支，故现网不触发**；未路由会话走全局默认档（`streaming_response=true` + `turn_off`），但 aiocqhttp 平台不支持流式消息（`support_streaming_message=false`），同样落在非流式。若你把 `streaming_response` 打开、或新增未路由会话走全局默认档，跨 chunk 标签可能穿链；且此时模型漏标签的兜底补插会落在**不投递**的 `STREAMING_FINISH` 链上空转（`respond/stage.py:179-180`），那一轮会彻底漏艾特。
3. **宿主升级回归点**：send 兜底渲染依赖 AstrBot 内部行为——`AstrMessageEvent.send` 可被实例属性遮蔽、respond stage 每次动态取 `event.send` / `send_streaming`、适配器 `send_streaming` 内部走 `self.send`。升级 AstrBot 大版本后请回归一次"分段 + 艾特"场景，否则兜底渲染可能静默失效。
4. **分段插件端到端未实测**：只做了注册表顺序核对与按其源码建模的投递验证（见上）。
5. **未验证**：`show_tool_use_status=true`（当前档案为 `false`）时，兜底补插是否会挂到工具状态消息上。
6. **已知取舍**：`[at:0123]` 由宿主归一为 `123`（pydantic `qq: int | str`）；`[at:+123]` 在插件侧直接降级为纯文本 `@+123`；转义写法 `\[at:123\]` 交付时会丢掉 `[` 前的反斜杠（概率极小，未处理）；"意图未被满足"告警按会话去重、无容量上限。
7. **性能**：没有 profiler 基准数据，只能说未观察到数量级退化，**不承诺**零回归。
8. **直连号窗口（v2.6.1 起，v2.6.2 已加成员校验）**：`allow_direct_qq_at=true`（默认）时，**当轮用户消息里出现的 5..12 位数字**才进入候选，且**必须同时是本群成员名单里的号码**（v2.6.2 起）——用户随口说的数字一旦被模型抄进 `[at:...]`，只要不是本群成员就会被降级；要更严就关掉 `allow_direct_qq_at`（只信任工具确认过的 ID）。且该来源**仅当轮有效、不跨轮记忆**：上一轮给号、本轮要求艾特会被降级（保守），请让 AI 走 `search_and_mention`。
9. **约束边界（v2.6.1）**：ID 可信来源约束治理的是 `[at:ID]` **标签**；上游插件**直接构造**的 `At` 组件不在管辖范围内（不是本插件渲染的）。另外，跨组件拼合出的可信 `At` 目前**不写审计**（既有实现细节）。
10. **上游吞标签（v2.6.1 新增留档）**：`meme_manager` 在 `on_llm_response` 阶段会吞掉**任意 `[...]` token**（不止艾特标签）；处置见[排障第四步](#第四步回复里的-atid-在群里凭空消失先查上游插件)。上游升级或改 `_make_meme_parser` 选项后需重新复现。
11. **配置不会热重载（v2.6.1 新增留档）**：改人设工具白名单或插件配置后必须重载/重启才生效，见[排障第五步](#第五步改了配置却不生效必须重载重启)。
12. **可信 ID 记忆的淘汰**：按插入顺序 FIFO、更新不刷新位置，容量 500 槽位下高活跃会话可能先被淘汰（低风险）；`_sender_key` 在无发送者事件时退化为共用槽位（低风险）。
13. **版本落位（写文档时的实测事实）**：运行中的实例 PID `3360763` 启动于 **2026-10-05 23:55:58**，而 `main.py` mtime 为 **2026-10-06 00:32:07** ⇒ **在线实例是 v2.6.3 代码、不含 v2.6.4 的提示词意图化**，需重载/重启才生效（是否重载由用户决定）。
14. **不在群里的号码无法真正被 @（平台限制，v2.6.2）**：不存在/非本群的 QQ 号永远无法构造出可投递的真艾特（平台 `retcode=1200` 会拒绝整条消息），v2.6.2 起一律以 `@<号码>` 文本呈现——可读，但不会触发提醒。
15. **名单不可用时直连号一律降级（v2.6.2 行为变化）**：私聊、名单拉取失败、平台返回空名单这几支都不再渲染 `At`；该窗口内**含 5..12 位数字的消息每次渲染会多花约 0.5s**（一次退避重试后降级；失败负缓存按裁定未采纳，即失败期间每次都多这 0.5s）。
16. **名单 180s 缓存窗口（v2.6.2）**：窗口内**新入群成员**的真实号码会被降级为 `@<号码>`（名单刷新后自愈：等 TTL 过期，或让 AI 做一次成员搜索）。**大群名单可能被截断或受权限限制**，导致名单外的合法成员被降级（真机截断未验证）。
17. **工具确认集不校验成员（v2.6.2 新增留档）**：成员校验只作用于直连号码；工具返回的 ID 不做二次校验——180s 窗口内**退群成员**仍可能被渲染并触发同类 `retcode=1200` 整条丢失（概率低）。
18. **审计 ≠ 投递成功（v2.6.2 新增留档）**：审计记的是"插件渲染放行"；线上 `2026-10-05T22:02:34` 有 `allowed: true` 却被平台 `1200` 拒收的实例，排障见[排障第六步](#第六步群里只有表情包正文全没了先看是不是平台拒收retcode1200)。
19. **消息含数字就会拉名单（v2.6.2）**：只要当轮消息里出现 5..12 位数字，即使最终回复没有任何标签也会尝试拉取名单（有 180s 缓存兜底；拉取失败时多花约 0.5s）。
20. **自目标真 @ 的三个前提缺一不可（v2.6.3）**：艾特"当前说话人自己"走真 `At` 需要同时满足「群聊 + 名单可用 + 发送者在名单内」；名单拉取失败/被截断、或说话人刚发言就退群 ⇒ 仍降级为 `@昵称`/`@号码`（避免平台 `1200` 整条拒收）。
21. **私聊不启用自目标例外（v2.6.3）**：私聊里 `At` 段不可解析，仍一律降级为文本。
22. **降级文案依赖名单（v2.6.3）**：名单拿不到时无法显示昵称，只能显示 `@<号码>`（此时仍会打聚合告警）。
23. **名字含标签语法时不作显示名（v2.6.3）**：成员把群名片/昵称设成 `[at:…]` 时，降级文案回退为 `@<号码>`（安全优先，避免标签原文经分段直发路径穿链）。
24. **拉取条件放宽的代价（v2.6.3 行为变化）**：只含标签、不含数字的回复也会触发一次名单拉取（为了拿昵称做降级文案；180s 缓存兜底，工具路径通常已预热）。
25. **标签后的空行会被收尾逻辑吃掉（v2.6.3 留档，行为同升级前）**：`前段 [at:X]\n\n后段` → `前段@X后段`，分段插件在该处无法切分。
26. **换行/名单相关排障入口**：[排障第七步](#第七步机器人为什么会-出一串数字)（为什么会 `@` 出一串数字）、[第六步](#第六步群里只有表情包正文全没了先看是不是平台拒收retcode1200)（整条消息消失）。
27. **`@数字` 不是真艾特（v2.6.4 澄清）**：降级文案里的 `@1234567890` 只是**纯文本**（QQ 里看起来像 `@`，但不触发提醒、不是 `At` 组件、也不写 `at_member` 审计）；别把它当成"插件真的艾特了这个人"。是否把降级文案换成更像文本的形态（如 `@1234567890（未确认，仅文本）`）属于产品取舍，当前未改。
28. **提示词是概率性手段（v2.6.4）**：意图规则只能提高模型"该调工具时调工具"的概率，**不能保证每次都对**；判断是否频繁失败看 journald 的 `[AtTool] WARN 艾特意图未被满足：本轮未调用 search_and_mention…`。
29. **面板 `llm_prompt` 未同步（v2.6.4）**：插件不代改用户配置——面板里那份旧触发词清单仍会注入并与新意图段叠加；它**可精简或留空且不影响功能**，是否精简由用户决定（非必须）。另外工具返回值文案仍写着"请直接使用 `[at:ID]` 标签"，与"纯查询不输出标签"在文本层面略有出入（未观测到实际影响，留档备查）。
