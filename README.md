## 核心能力

### 🎯 search_and_mention：让 LLM 自己找人

LLM 通过 `search_and_mention` 工具按昵称/群名片搜索群成员，工具返回**紧凑结果**（仅含命中成员的群名片/昵称、QQ 号、角色标注，以及可直接使用的 `[at:ID]` 标签），省 Token 不废话——本DS特意调过的，哼～才不是为了让你的 API 账单好看呢。

### 🔍 模糊匹配（`enable_fuzzy_search`，默认开）

开启后支持**子串包含匹配**：搜「柴」能找到「柴郡」，搜「武」能捞到「武藏」。用户说「帮我艾特姓柴的」「艾特一下那个叫武的bot」这类模糊指代，LLM 提取关键词就能命中。关闭后必须完全匹配才放行。

> 💡 小知识：搜索结果会带角色中文标注（群主/管理员/成员），多候选列表也逐条标注角色——「艾特群主」这种角色指代，LLM 能结合角色标注判断该点谁。

### ✨ 真实 At 渲染

LLM 只需在回复正文里放 `[at:ID]` 标签（比如 `[at:10086]`），插件就会把它渲染成真正的 `At` 组件。`[at:ID1][at:ID2]` 连续多个标签？一次艾特一群人，没问题～ 🐳

### 🛡️ 角色卡约束免疫

角色卡常见的「禁止方括号」「只能纯文本回复」类约束，容易让 LLM 把标签吞掉。本插件对付它的方式是**机制级兜底**：

- 默认提示词内置**红线条款**：禁止把工具返回的原始文本直接发给用户、禁止描述工具调用过程（「让我查查」「找到了」都不行）、禁止捏造用户 ID；
- 即使 LLM 真的因为角色卡约束省略了标签，**兜底补插**机制也会在整轮渲染时按「唯一命中」自动补回 `[at:ID]`——艾特照样不丢。

（本DS才不是在夸这个设计有多妙，只是……哼，你们用就完事了。）

### 🧊 延迟渲染 + send 兜底：双保险

- **延迟渲染**：`[at:ID]` 以纯文本形式贯穿所有中间插件（第三方插件随便重建消息链，只要保留文本就没事），由本插件在 `on_decorating_result` **最后阶段**（priority=-1000）统一渲染为 At 组件；
- **send 兜底**：万一有插件（比如分段插件）清空消息链后直接 `event.send()` 裸文本？没关系——本插件在请求阶段就给事件实例装上了 send 包装，消息真正发往平台**前一刻**再兜底渲染一次。

两条路径共用同一渲染流水线，任何第三方插件都别想破坏艾特。哼～

### 🧩 跨组件碎片恢复

标签被切碎了？照样给你拼回来：

- 相邻 Plain 组件先自动合并（`[at:12` + `345]` 分处两段？合并后完整匹配）；
- 跨组件切碎（前缀和闭合括号分处不同组件、**中间隔着 At 组件**）→ 跨组件拼合，原位恢复；
- **零宽字符污染**（`\u200b` 混进标签里）→ 零宽视为透明，清洗后重新暴露完整标签，恢复渲染。

### 🩹 残缺标签容错

实在恢复不了的残缺 `[at:` 残留？**按纯文本原样保留，绝不误删用户文本**，同时打 warning 日志方便排查。宁可丑，不能丢内容，这是本DS的底线。

### 👥 多目标艾特

`[at:ID1][at:ID2][at:ID3]`——LLM 可以在一条回复里艾特多人，插件逐个渲染，一个都不少。

### 📢 @全体（权限验证 + 冷却）

- 输出 `[at:all]` 即可触发 @全体；
- `permission_verification`（默认开）：仅**群主、管理员或 Bot 超级管理员**可以触发，普通成员要求 @全体时 LLM 会被明确告知无权限并改用自然语言说明；
- `at_all_cooldown`（默认 60 秒）：同一群两次 @全体 的最小间隔，冷却内的第二次会被自动**降级为纯文本「@全体成员」**，并向操作者反馈受限原因（冷却中，剩余约 X 秒）。

### 🔒 会话白名单 / 黑名单

- `session_whitelist`：仅允许列表内的会话使用艾特（条目可为完整 UMO，用 `/sid` 获取；或直接填群号）；留空 = 全部允许；
- `session_blacklist`：禁止列表内的会话使用；**黑名单优先级高于白名单**；
- 命中禁止会话时，`[at:ID]` 会被剥离、`[at:all]` 降级为纯文本「@全体成员」，不会漏发。

### 🪄 兜底补插（LLM 漏标签也不怕）

`search_and_mention` **唯一命中**成员时写入会话级兜底缓存（TTL 120 秒）；若 LLM 最终回复里没有携带任何 `[at:ID]` 标签，插件会在整轮渲染时自动补插标签完成艾特。关键设计：

- **仅在整轮最后渲染时消费**（主钩子唯一入口），send 兜底路径绝不补插——多段直发时每段各补一次导致**重复艾特**？不存在的；
- 缓存**一次性消费**，读取即删除，跨轮次误用？不存在的；
- 回复中已有其他来源插入的 At 组件时自动放弃补插，绝不重复艾特。

### 📋 审计日志（`enable_audit_log`，默认开）

每次生效的艾特（@单人逐条 / @全体放行 / @全体被拦截）都会落盘一条 JSONL 审计记录到插件数据目录的 `audit/at_audit_YYYYMMDD.jsonl`（按日切割），字段包含：时间、群号、操作者、操作类型（`at_member`/`at_all`）、目标、是否放行、原因。谁艾特了谁、被没被拦，一目了然——本DS可不喜欢背黑锅，哼～

## v2.5.1 修复了什么

本版本（fork 维护版）针对 v2.3.x 遗留的 4 项缺陷做了定点修复，详见 [CHANGELOG.md](CHANGELOG.md)：

1. **修复同轮回复重复艾特**：多段直发 + 兜底缓存组合场景下，同一成员被重复艾特 → 兜底补插与缓存消费改为仅由主钩子成对执行；
2. **修复 `[at:ID]` 裸文本穿链发出**：流式 fallback 把标签切碎后，标签以纯文本裸奔发到群里 → 新增宽松恢复机制；
3. **修复跨组件切碎标签无法恢复**：前缀与闭合括号分处不同组件（中间隔 At 组件/混入零宽字符）时无法还原 → 跨组件拼合恢复；
4. **修复跨轮次误艾特**：主钩子链空时兜底缓存残留，导致新一轮回复被误补插上一轮成员 → 链空时一并解除缓存。

## 配置

安装后**开箱即用**，无需任何配置即可使用全部核心功能。以下配置项在 AstrBot 插件管理面板中调整：

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `permission_verification` | bool | `true` | @全体 权限验证。开启后仅群主、管理员或 Bot 超级管理员可触发 @全体 |
| `allow_direct_qq_at` | bool | `true` | 允许直接使用 QQ 号艾特。开启后用户直接给 QQ 号即可让 Bot 艾特；关闭后必须通过搜索群成员确认存在 |
| `enable_fuzzy_search` | bool | `true` | 模糊昵称搜索。开启后支持子串部分匹配（搜「张」可找到「张三」）；关闭后必须完全匹配 |
| `session_whitelist` | list | `[]` | 会话白名单。条目可为完整 UMO（用 `/sid` 获取）或群号；留空表示允许全部会话 |
| `session_blacklist` | list | `[]` | 会话黑名单。格式同白名单；黑名单优先级高于白名单 |
| `llm_prompt` | text | 内置默认 | LLM 自定义提示词基底（艾特格式说明 + 红线条款），Markdown 编辑 |
| `at_all_cooldown` | int | `60` | @全体 冷却秒数。0 = 不限制；冷却内第二次 @全体 自动降级纯文本并反馈原因 |
| `enable_audit_log` | bool | `true` | 艾特操作审计日志。落盘到插件数据目录 `audit/at_audit_YYYYMMDD.jsonl`（JSONL，按日切割） |
| `member_list_cache_ttl` | int | `180` | 群成员列表缓存秒数。千人级大群搜索时复用列表、减少全量拉取；0 = 不缓存 |

## 使用示例

装完即用，在群聊里直接跟 Bot 说就行～

### 场景 1：单目标艾特

> **用户**：@Bot 帮我艾特一下张三，喊他上线打游戏。
>
> **Bot（后台动作）**：
> 1. 调用 `search_and_mention(name="张三")` 查询群成员；
> 2. 唯一命中「张三（10086，成员）」，得到标签 `[at:10086]`；
> 3. 把标签放进回复正文，最终由插件渲染为真实 At 组件。
>
> **Bot（实际回复）**：@张三 喊他上线打游戏。

### 场景 2：模糊/角色指代

> **用户**：@Bot 帮我艾特一下姓柴的。
>
> **Bot（后台动作）**：
> 1. 提取搜索关键词「柴」，调用 `search_and_mention(name="柴")`；
> 2. 模糊匹配命中唯一成员「柴郡（1024，管理员）」→ `[at:1024]`。
>
> **Bot（实际回复）**：@柴郡 收工了，来冒个泡～

> **用户**：@Bot 艾特一下群主。
>
> **Bot（后台动作）**：搜索并结合结果中的角色标注（群主/管理员/成员）判断目标；若搜索词命中多个候选，会列出带角色标注的编号列表请用户确认。

### 场景 3：多目标艾特

> **用户**：@Bot 艾特一下武藏和长风，说今晚开黑。
>
> **Bot（后台动作）**：依次搜索两人，得到 `[at:20001][at:20002]`，一条回复渲染出两个真实 At。
>
> **Bot（实际回复）**：@武藏 @长风 今晚八点开黑，别迟到～

### 场景 4：多候选确认

> **用户**：@Bot 艾特张伟。
>
> **Bot（后台动作）**：搜「张伟」命中 3 个候选（带序号 + 角色），请用户选择；用户回复序号后调用 `select_member_by_index` 获取最终标签（候选记录 120 秒内有效，过期需重新搜索）。

### 场景 5：@全体

> **用户**：@Bot 艾特全体成员，通知明天维护。
>
> **Bot（后台动作）**：输出 `[at:all]` → 插件校验操作者权限（群主/管理员/超管）+ 冷却（默认 60 秒）→ 放行则渲染真实 @全体，拦截则降级纯文本「@全体成员」并反馈原因。

## 工作原理

```
LLM 请求阶段
  └─ on_llm_request：注入格式指令 + 红线条款 + @全体权限提示
      └─ 同时给事件实例安装 send 兜底渲染包装（幂等，只装一次）

LLM 调用工具
  └─ search_and_mention / select_member_by_index → 拿到 [at:ID] 标签
      └─ 唯一命中时写入会话级兜底缓存（TTL 120s）

结果阶段（所有第三方插件之后）
  └─ on_decorating_result（priority=-1000，最后执行）
      ① 合并相邻 Plain（标签被拆到相邻组件 → 先拼起来）
      ② 无标签？→ 兜底补插（仅此路径消费缓存，一次性）
      ③ 会话准入（白/黑名单，禁止则剥离标签/降级 @全体）
      ④ @全体 权限 + 冷却判定
      ⑤ [at:ID] / [at:all] → 渲染为真实 At 组件
      ⑥ 审计落盘（JSONL 按日切割）
      ⑦ 收尾：零宽清理 / 碎片宽松恢复 / 残缺告警（按纯文本保留）

发送前一刻（兜底）
  └─ 第三方插件清链直发？→ send 包装再渲染一次（只渲染已有标签，绝不补插）
```

一句话：**标签以纯文本活到最后，渲染只在最后和最后一刻各做一次，补插只认主钩子**。哼～这下你们总该放心了吧？

## 兼容性与注意事项

1. **平台限制**：本插件依赖 aiocqhttp 平台（OneBot V11 协议，如 NapCat 等），**仅支持 QQ 平台**；
2. **群聊限制**：获取群成员列表功能仅在群聊环境中有效，私聊无法使用；
3. **权限要求**：Bot 账号需要有获取群成员列表的权限（通常默认都有）；
4. **AstrBot 版本**：要求 **AstrBot >= 4.26.0**；
5. **角色卡冲突**：若角色卡明确「禁止方括号」等约束，LLM 可能省略标签——本插件的兜底补插机制会尽量补救（详见[角色卡约束免疫](#角色卡约束免疫)），但建议在角色卡中为本插件标签留出余地；
6. **版本号**：本 fork 版本为 **v2.5.1**，`metadata.yaml` 中 `astrbot_version: ">=4.26.0"`。
