# 🐋 AtTool —— 让 LLM 学会「真·艾特」（AstrBot 艾特工具）

**一句话简介**：让你的 AstrBot 拥有「真正」艾特群成员的能力。LLM 可以查询群成员列表（昵称/群名片/QQ 号），并在回复中输出 `[at:ID]` 标签，由本插件在消息发出前统一渲染为 QQ 的**真实 At 组件**（会触发提醒的那种，不是 `@` 开头的假把式）。

## 核心能力

### 🎯 search_and_mention：让 LLM 自己找人

LLM 通过 `search_and_mention` 工具按昵称/群名片搜索群成员，工具返回**紧凑结果**（仅含命中成员的群名片/昵称、QQ 号、角色标注，以及可直接使用的 `[at:ID]` 标签），省 Token 不废话——本DS特意调过的，哼～才不是为了让你的 API 账单好看呢。

### 🔍 模糊匹配（`enable_fuzzy_search`，默认开）

开启后支持**子串包含匹配**：搜「柴」能找到「柴郡」，搜「武」能捞到「武藏」。用户说「帮我艾特姓柴的」「艾特一下那个叫武的bot」这类模糊指代，LLM 提取关键词就能命中。关闭后必须完全匹配才放行。

> 💡 小知识：搜索结果会带角色中文标注（群主/管理员/成员），多候选列表也逐条标注角色——「艾特群主」这种角色指代，LLM 能结合角色标注判断该点谁。

### ✨ 真实 At 渲染

LLM 只需在回复正文里放 `[at:ID]` 标签（比如 `[at:10086]`），插件就会把它渲染成真正的 `At` 组件。`[at:ID1][at:ID2]` 连续多个标签？一次艾特一群人，没问题～ 🐳

### 🛡️ 角色卡约束免疫

角色卡常见的「禁止方括号」「只能纯文本回复」类约束，容易让 LLM 把标签吞掉。本插件对付它的方式是**机制级兜底**：

- 默认提示词内置**红线条款**：禁止把工具返回的原始文本直接发给用户、禁止描述工具调用过程（「让我查查」「找到了」都不行）、禁止捏造用户 ID；
- 即使 LLM 真的因为角色卡约束省略了标签，**兜底补插**机制也会在整轮渲染时按「唯一命中」自动补回 `[at:ID]`——艾特照样不丢。

（本DS才不是在夸这个设计有多妙，只是……哼，你们用就完事了。）

### 🧊 延迟渲染 + send 兜底：双保险

- **延迟渲染**：`[at:ID]` 以纯文本形式贯穿所有中间插件（第三方插件随便重建消息链，只要保留文本就没事），由本插件在 `on_decorating_result`（priority=-1000，实测**早于**分段插件的 -1e17）统一渲染为 At 组件——先渲染、后分段，标签不会被分段切走；
- **send 兜底**：万一有插件清空消息链后直接 `event.send()` 裸文本？本插件在请求阶段就给事件实例装上了 send 包装，消息真正发往平台**前一刻**再渲染一次链内已有的标签。

两条路径共用同一渲染流水线。**v2.6.0 起 send 兜底只渲染链内已有的标签，绝不补插、绝不消费兜底缓存、绝不剥离其他段的标签**——逐段发送时不再改写分段结果（旧实现会把 At 补到第一段、或把后续段的真实标签当"重复"剥离）。补插只发生在主钩子（整轮渲染）这一处。

### 🧩 跨组件碎片恢复

标签被切碎了？照样给你拼回来：

- 相邻 Plain 组件先自动合并（`[at:12` + `345]` 分处两段？合并后完整匹配）；
- 跨组件切碎（前缀和闭合括号分处不同组件、**中间隔着 At 组件**）→ 跨组件拼合，原位恢复；
- **零宽字符污染**（`\u200b` 混进标签里）→ 零宽视为透明，清洗后重新暴露完整标签，恢复渲染。

### 🩹 残缺标签容错

恢复不了的残缺标签按形态分别处理，**绝不把标签语法留在交付文本里、也绝不误删你的正文**：

- 载荷无法解析（`[at:柴郡]`、`[at:ID]`、`[at:１２３]`、超长数字）→ 降级为可读纯文本 `@载荷`，并打 warning；
- 空载荷（`[at:]`、`[at: ]`）→ 删除标签语法；
- 未闭合（整条链里始终没有 `]`，如 `[at: 123`）→ 删除 `[at:` 语法片段、保留其余正文（`123`），并打 warning；
- 收尾后正文里若仍有标签语法残留（一般是被第三方插件在分段/重建时切断）→ 记一条 warning 便于排查。

完整形态对照表见[标签形态与降级规则](#标签形态与降级规则)。

### 👥 多目标艾特

`[at:ID1][at:ID2][at:ID3]`——LLM 可以在一条回复里艾特多人，插件逐个渲染，一个都不少。

### 📢 @全体（权限验证 + 冷却）

- 输出 `[at:all]` 即可触发 @全体；
- `permission_verification`（默认开）：仅**群主、管理员或 Bot 超级管理员**可以触发，普通成员要求 @全体时 LLM 会被明确告知无权限并改用自然语言说明；
- `at_all_cooldown`（默认 60 秒）：同一群两次 @全体 的最小间隔，冷却内的第二次会被自动**降级为纯文本「@全体成员」**，并向操作者反馈受限原因（冷却中，剩余约 X 秒）。

### 🔒 会话白名单 / 黑名单

- `session_whitelist`：仅允许列表内的会话使用艾特（条目可为完整 UMO，用 `/sid` 获取；或直接填群号）；留空 = 全部允许；
- `session_blacklist`：禁止列表内的会话使用；**黑名单优先级高于白名单**；
- 命中禁止会话时，`[at:ID]` 会被剥离、`[at:all]` 降级为纯文本「@全体成员」、非数字载荷转纯文本 `@载荷`（大小写 / 全角 / 带空格形态同样处理）。

### 🪄 兜底补插（LLM 漏标签也不怕）

`search_and_mention` **唯一命中**成员时写入会话级兜底缓存（TTL 120 秒）；若 LLM 最终回复里没有携带任何 `[at:ID]` 标签，插件会在整轮渲染时自动补插标签完成艾特。关键设计：

- **仅由主钩子消费**（整轮渲染的唯一补插入口），send 兜底路径绝不补插——多段直发时每段各补一次导致**重复艾特**？不存在的；
- 缓存**一次性消费**，读取即删除，跨轮次误用？不存在的；
- 回复中已有其他来源插入的 At 组件时自动放弃补插，绝不重复艾特。

### 📋 审计日志（`enable_audit_log`，默认开）

每次生效的艾特（@单人逐条 / @全体放行 / @全体被拦截）都会落盘一条 JSONL 审计记录到插件数据目录的 `data/plugin_data/astrbot_plugin_AtTool/audit/at_audit_YYYYMMDD.jsonl`（按日切割），字段包含：时间、群号、操作者、操作类型（`at_member`/`at_all`）、目标、是否放行、原因。谁艾特了谁、被没被拦，一目了然——本DS可不喜欢背黑锅，哼～

> 注意：审计记录写在**渲染阶段**，模型没输出标签、或标签被降级/剥离时不会有记录——"没有审计行"不等于"用户没有艾特意图"（那类情况看[排障](#排障)里的告警日志）。

## 标签形态与降级规则

LLM（以及宿主序列化进历史上下文的内容）会写出各种形态的艾特标签。**v2.6.0 起**下列形态全部被接受——大小写、半角/全角冒号、冒号两侧的空白与零宽字符都会先归一：

| 输入形态 | 处理结果 |
| --- | --- |
| `[at:123]` `[At:123]` `[AT:123]` `[aT:123]` | → 真实 At 组件（`At(qq="123")`） |
| `[at: 123]` `[at：123]` `[at : 123]` | → `At(qq="123")`（冒号两侧空白、全角冒号） |
| `[at<零宽>:123]` `[<零宽>at:123]` `[at:12<零宽>3]` `[at:<零宽>123]` | → `At(qq="123")`（零宽字符视为透明） |
| `[at:all]` `[At:All]` | → 走 @全体 权限 + 冷却判定（放行 = 真实 @全体；拦截 = 纯文本「@全体成员」） |
| `[at:柴郡]` `[at:ID]` `[at:１２３]` | → 降级纯文本 `@柴郡` / `@ID` / `@１２３` + warning（**不**产生 At） |
| `[at:1234567890123]`（超过 12 位数字） | → 降级纯文本 `@1234567890123` + warning |
| `[at:]` `[at: ]` | → 删除标签语法 |
| `[at:123`（始终没有 `]`） | → 删除 `[at:` 语法片段、保留其余正文 + warning |
| `[at 123]` `[at]` `[avatar:1]` | → 普通文本，原样保留（**不是**标签） |

规则小结：

- **只有 1..12 位 ASCII 数字或 `all` 才会变成真实艾特**；其它载荷一律降级为可读文本，不会出现"艾特到不存在的人"或"非法 QQ 号"；
- 被切碎的标签会先尝试拼合恢复：相邻 Plain 合并、跨组件拼合（前缀与 `]` 分处不同组件、中间隔着 At 组件）、多处零宽污染循环恢复（单链上限 8 轮）；
- 禁止艾特的会话（`session_blacklist`，或不在 `session_whitelist`）按同一套规则处理：成员标签剥离、`[at:all]` 转纯文本「@全体成员」、非数字载荷转 `@载荷`；
- 宿主会把可整数化的载荷归一（`[at:0123]` 交付时是 `At(qq=123)`），插件不再额外处理前导零，也不做"名字 → 成员"的猜测。

## v2.6.0 修复了什么

本版本针对四项反馈（AI 不调用工具 / 标签裸文本泄漏 / 与分段插件互操作时艾特错位 / 其它卫生问题）做了定点修复，完整清单见 [CHANGELOG.md](CHANGELOG.md)：

1. **标签形态容错**：旧版只认 `[at:数字]`（小写 + 半角冒号 + 冒号后无空白），`[At:123]`、`[at：123]`、`[at: 123]`、`[at:１２３]` 等形态会**原样发到群里**（而且大写形态下"泄漏"与"误艾特"还会同时发生）；现在统一归一，见[标签形态与降级规则](#标签形态与降级规则)；
2. **非法/超长载荷降级**：`[at:柴郡]`、`[at:１２３]`、超长数字不再产出非法或不存在的 At 目标；
3. **send 路径收敛**：发送前的兜底渲染只渲染已有标签，不再补插/剥离，修复逐段直发时"@ 被补到第一段""真实标签被剥离""艾特到错误的人"；
4. **兜底补插绑定发起者**：同一会话里他人接话，不再被补插上一位用户搜索到的成员；
5. **工具描述强化 + 工具不可达降级**：`search_and_mention` 的 docstring 明确"要艾特就必须先调用本工具"；工具被人设白名单挡住时改为注入"未启用艾特工具"的降级提示并打一次性告警，而不是要求模型调用一个它拿不到的工具（**注意：这不能替代面板侧勾选，见[排障](#排障)**）；
6. **工程**：标签语法收敛为单一事实来源；测试 174 → 412（全部通过）；ruff 违规数（源码 / 含测试）63 → 53、91 → 81，未新增。

## v2.5.1 修复了什么

> v2.5.2 的内容（成员别名映射兜底搜索、艾特意图可观测性日志）见 [CHANGELOG.md](CHANGELOG.md)。

本版本（fork 维护版）针对 v2.3.x 遗留的 4 项缺陷做了定点修复，详见 [CHANGELOG.md](CHANGELOG.md)：

1. **修复同轮回复重复艾特**：多段直发 + 兜底缓存组合场景下，同一成员被重复艾特 → 兜底补插与缓存消费改为仅由主钩子成对执行；
2. **修复 `[at:ID]` 裸文本穿链发出**：流式 fallback 把标签切碎后，标签以纯文本裸奔发到群里 → 新增宽松恢复机制；
3. **修复跨组件切碎标签无法恢复**：前缀与闭合括号分处不同组件（中间隔 At 组件/混入零宽字符）时无法还原 → 跨组件拼合恢复；
4. **修复跨轮次误艾特**：主钩子链空时兜底缓存残留，导致新一轮回复被误补插上一轮成员 → 链空时一并解除缓存。

## 配置

安装后**开箱即用**，无需任何配置即可使用全部核心功能。以下配置项在 AstrBot 插件管理面板中调整：

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `permission_verification` | bool | `true` | @全体 权限验证。开启后仅群主、管理员或 Bot 超级管理员可触发 @全体 |
| `allow_direct_qq_at` | bool | `true` | 允许直接使用 QQ 号艾特。开启后用户直接给 QQ 号即可让 Bot 艾特；关闭后必须通过搜索群成员确认存在 |
| `enable_fuzzy_search` | bool | `true` | 模糊昵称搜索。开启后支持子串部分匹配（搜「张」可找到「张三」）；关闭后必须完全匹配 |
| `session_whitelist` | list | `[]` | 会话白名单。条目可为完整 UMO（用 `/sid` 获取）或群号；留空表示允许全部会话 |
| `session_blacklist` | list | `[]` | 会话黑名单。格式同白名单；黑名单优先级高于白名单 |
| `llm_prompt` | text | 内置默认 | LLM 自定义提示词基底（艾特格式说明 + 红线条款），Markdown 编辑 |
| `at_all_cooldown` | int | `60` | @全体 冷却秒数。0 = 不限制；冷却内第二次 @全体 自动降级纯文本并反馈原因 |
| `enable_audit_log` | bool | `true` | 艾特操作审计日志。落盘到插件数据目录 `audit/at_audit_YYYYMMDD.jsonl`（JSONL，按日切割） |
| `member_list_cache_ttl` | int | `180` | 群成员列表缓存秒数。千人级大群搜索时复用列表、减少全量拉取；0 = 不缓存 |
| `member_aliases` | list | `[]` | 成员别名映射（搜索兜底）。兼容 `{"才俊": "柴郡"}` 字典与 `["才俊=柴郡"]` 列表两种写法；真名/群名片精确与模糊均未命中时，按别名展开再搜一次 |

> **v2.6.0 未新增配置项**（`_conf_schema.json` 无改动），旧配置无需迁移；本版本的日志与降级行为由既有配置控制。

## 使用示例

装完即用，在群聊里直接跟 Bot 说就行～

### 场景 1：单目标艾特

> **用户**：@Bot 帮我艾特一下张三，喊他上线打游戏。
>
> **Bot（后台动作）**：
> 1. 调用 `search_and_mention(name="张三")` 查询群成员；
> 2. 唯一命中「张三（10086，成员）」，得到标签 `[at:10086]`；
> 3. 把标签放进回复正文，最终由插件渲染为真实 At 组件。
>
> **Bot（实际回复）**：@张三 喊他上线打游戏。

### 场景 2：模糊/角色指代

> **用户**：@Bot 帮我艾特一下姓柴的。
>
> **Bot（后台动作）**：
> 1. 提取搜索关键词「柴」，调用 `search_and_mention(name="柴")`；
> 2. 模糊匹配命中唯一成员「柴郡（1024，管理员）」→ `[at:1024]`。
>
> **Bot（实际回复）**：@柴郡 收工了，来冒个泡～

> **用户**：@Bot 艾特一下群主。
>
> **Bot（后台动作）**：搜索并结合结果中的角色标注（群主/管理员/成员）判断目标；若搜索词命中多个候选，会列出带角色标注的编号列表请用户确认。

### 场景 3：多目标艾特

> **用户**：@Bot 艾特一下武藏和长风，说今晚开黑。
>
> **Bot（后台动作）**：依次搜索两人，得到 `[at:20001][at:20002]`，一条回复渲染出两个真实 At。
>
> **Bot（实际回复）**：@武藏 @长风 今晚八点开黑，别迟到～

### 场景 4：多候选确认

> **用户**：@Bot 艾特张伟。
>
> **Bot（后台动作）**：搜「张伟」命中 3 个候选（带序号 + 角色），请用户选择；用户回复序号后调用 `select_member_by_index` 获取最终标签（候选记录 120 秒内有效，过期需重新搜索）。

### 场景 5：@全体

> **用户**：@Bot 艾特全体成员，通知明天维护。
>
> **Bot（后台动作）**：输出 `[at:all]` → 插件校验操作者权限（群主/管理员/超管）+ 冷却（默认 60 秒）→ 放行则渲染真实 @全体，拦截则降级纯文本「@全体成员」并反馈原因。

## 工作原理

```
LLM 请求阶段
  └─ on_llm_request：注入格式指令 + 红线条款 + @全体权限提示
      └─ 同时给事件实例安装 send 兜底渲染包装（幂等，只装一次）

LLM 调用工具
  └─ search_and_mention / select_member_by_index → 拿到 [at:ID] 标签
      └─ 唯一命中时写入会话级兜底缓存（TTL 120s）

结果阶段（分段插件之前：priority=-1000，早于 splitter 的 -1e17）
  └─ on_decorating_result
      ① 合并相邻 Plain + 跨组件拼合（标签被拆到相邻/分散组件 → 先拼回来）
      ② 无标签？→ 兜底补插（仅此路径消费缓存，一次性）
      ③ 会话准入（白/黑名单，禁止则剥离标签 / 降级 @全体 / 非数字载荷转 @载荷）
      ④ @全体 权限 + 冷却判定
      ⑤ [at:ID] / [at:all] → 渲染为真实 At 组件
      ⑥ 审计落盘（JSONL 按日切割，同事件同目标只记一条）
      ⑦ 收尾：零宽清理 / 空组件剔除 / 相邻合并 / 未闭合语法删除 / 残留告警

发送前一刻（兜底）
  └─ 第三方插件清链直发？→ send 包装再渲染一次（只渲染已有标签，绝不补插）
```

一句话：**标签以纯文本活到渲染钩子，渲染在主钩子与发送前一刻各做一次（同一流水线），补插只认主钩子**。哼～这下你们总该放心了吧？

## 兼容性与注意事项

1. **平台限制**：本插件依赖 aiocqhttp 平台（OneBot V11 协议，如 NapCat 等），**仅支持 QQ 平台**；
2. **群聊限制**：获取群成员列表功能仅在群聊环境中有效，私聊无法使用；
3. **权限要求**：Bot 账号需要有获取群成员列表的权限（通常默认都有）；
4. **AstrBot 版本**：要求 **AstrBot >= 4.26.0**；
5. **角色卡冲突**：若角色卡明确「禁止方括号」等约束，LLM 可能省略标签——本插件的兜底补插机制会尽量补救（详见[角色卡约束免疫](#角色卡约束免疫)），但建议在角色卡中为本插件标签留出余地；
6. **版本号**：本 fork 版本为 **v2.6.0**，`metadata.yaml` 中 `astrbot_version: ">=4.26.0"`；
7. **会话人设的「工具」白名单**：若白名单未勾选 `search_and_mention` / `select_member_by_index`，AI 拿不到艾特工具——这是「需要艾特时 AI 不调用工具」的决定性原因，必须由运维在面板侧处理，见[排障](#排障)。

## 与分段插件（splitter）共存

分段插件会把一条回复拆成多段投递，艾特组件归到哪一段由它的 `at_strategy` 决定。**本部署实测配置为 `at_strategy = 跟随下段`**（`data/config/astrbot_plugin_splitter_config.json` → `reply_media_settings.at_strategy`），推荐保持该值（`嵌入` 亦可）。原因：

- 钩子执行顺序实测为：`priority=0` 的普通钩子 → **本插件（-1000）** → **分段插件（-1e17）**（AstrBot 按 `-priority` 降序执行）。也就是**本插件先把整条链里的标签渲染成 At，分段插件再对渲染后的链分段**——"跟随下段"会把 At 交到紧随其后的那一段，艾特不会丢在中间；
- v2.6.0 起本插件的 send 兜底渲染**不再改写分段结果**（不补插、不剥离），所以分段插件逐段 `event.send` 也是安全的；
- 分段插件分段后走的是 `context.send_message` 直发（**不经过** `event.send`），本插件的 send 包装看不到这条消息——此时能否艾特，仍由"标签在分段前已渲染成 At"保证，也就是上面的执行顺序。

**建议**：① 保持 `at_strategy = 跟随下段`（或 `嵌入`）；② 不要把标签当作"要清理的文本"——若你在分段插件里配了清理正则/清理词，请避开 `[at:...]` 形态；③ 让分段插件把回复正文里的标签原样保留（本插件的延迟渲染依赖纯文本标签活到 `on_decorating_result`）。

**已知边界**：若有插件在 **priority 高于 -1000** 的阶段清空消息链并直接发送，本插件的主钩子会看到空链（无法补插），且那条直发消息不经过本插件的 send 包装——该场景下不承诺补插（本版本非目标）。

> 附：本版本对分段插件只做了注册表顺序核对与按其源码建模的投递语义验证，**没有真跑它的 `on_decorating_result`**；若它改了 `at_strategy` 或改走 `event.send` 直发，请重跑一次真机复测。

## 排障

### 第一步：确认会话人设的「工具」白名单（最常见原因）

**用户要求艾特、AI 却不调用工具，决定性原因通常不在插件、而在配置**：AstrBot 在会话人设里配置「工具」白名单时，只会把白名单内的工具交给模型；若白名单里没有 `search_and_mention`（和 `select_member_by_index`），模型**根本拿不到**这个工具——插件无法在代码侧补回（只能注入降级提示 + 告警）。

> **运维提示（不是"已修复"）**：面板 → 人设（或该会话绑定的配置）→ 工具 → 勾选 `search_and_mention` / `select_member_by_index`；或把该会话人设切到已放行的「ds娘」。改完后在真实群里让 Bot 艾特一次做复测。
>
> 本版本只在插件侧做了两件事：工具不可达时注入降级提示（不让模型去调用一个不存在的工具）+ 打一条一次性告警。该问题**未在真实群验证为已修复**（沙箱里没有真实 QQ 消息轨迹），请以真实群复测为准。

### 第二步：看日志区分类别

| 现象 | 日志线索 | 说明 |
| --- | --- | --- |
| 群里出现 `[at:...]` 原文 | `标签载荷无法解析（…），已降级为纯文本` / `检测到未闭合的 [at: 标签语法` / `检测到 [at: 标签语法残留` | 载荷本身非法，或标签被第三方插件在分段/重建时切断 |
| 要求艾特但没艾特 | `本轮请求工具集不含 search_and_mention（会话 …），已注入降级提示；当前可用工具: …` | **人设工具白名单没勾选**（每会话只报一次） |
| 同上，但没有上面那条 | `艾特意图未被满足：本轮未调用 search_and_mention，最终回复也无艾特标签` | 提示词已注入且工具可用 → 是模型自己没调工具（每会话只报一次） |
| 同上 | `检测到艾特意图，已注入艾特指令`（info） | 只证明提示词注入成功，不代表模型会调用 |
| 该艾特的人没被艾特 | `兜底补插 [at:…]：LLM 回复未携带艾特标签` | 模型漏了标签，插件按唯一命中补插了一次 |
| 搜不到人 | `search_and_mention 未命中: 关键词=「…」（包含/完全匹配，会话 …）` | 关键词不匹配；可在 `member_aliases` 里补别名 |

### 第三步：查审计日志

- 路径：`data/plugin_data/astrbot_plugin_AtTool/audit/at_audit_YYYYMMDD.jsonl`（按日切割，`enable_audit_log` 控制开关）；
- 字段：`time` / `group_id` / `operator_id` / `op_type`（`at_member` / `at_all`）/ `target_id` / `allowed` / `reason`；
- 用途：确认"这次艾特有没有放行、被谁触发、为什么被拦"。注意：审计只覆盖**成功渲染**的艾特（含 @全体 被拦截的那一条），模型没输出标签时不会有记录。

## 已知限制

> 以下为**未修复 / 未验证 / 残余风险**项，v2.6.0 不做承诺；写在这里是为了让运维判断有正确前提。

1. **会话人设工具白名单（配置层，反馈①的真根因）**：见[排障](#排障)——插件侧只做了降级提示与告警，真正的动作在面板勾选；勾选之前，"需要艾特时 AI 不调用工具"仍会复现。
2. **流式跨 chunk 标签**：同一标签被切成 `chunk1='前缀[at:12'` / `chunk2='3] 后缀'` 时，第一个 chunk 的交付文本会保留标签语法（仅单个 chunk 内完整时才渲染）。**主群路由档案（`abconf_596ffb44`）实测 `streaming_response=false` + `unsupported_streaming_strategy=realtime_segmenting`，不进流式分支，故现网不触发**；未路由会话走全局默认档（`streaming_response=true` + `turn_off`），但 aiocqhttp 平台不支持流式消息（`support_streaming_message=false`），同样落在非流式。若你把 `streaming_response` 打开、或新增未路由会话走全局默认档，跨 chunk 标签可能穿链；且此时模型漏标签的兜底补插会落在**不投递**的 `STREAMING_FINISH` 链上空转（`respond/stage.py:179-180`），那一轮会彻底漏艾特。
3. **宿主升级回归点**：send 兜底渲染依赖 AstrBot 内部行为——`AstrMessageEvent.send` 可被实例属性遮蔽、respond stage 每次动态取 `event.send` / `send_streaming`、适配器 `send_streaming` 内部走 `self.send`。升级 AstrBot 大版本后请回归一次"分段 + 艾特"场景，否则兜底渲染可能静默失效。
4. **分段插件端到端未实测**：只做了注册表顺序核对与按其源码建模的投递验证（见上）。
5. **未验证**：`show_tool_use_status=true`（当前档案为 `false`）时，兜底补插是否会挂到工具状态消息上。
6. **已知取舍**：`[at:0123]` 由宿主归一为 `123`（pydantic `qq: int | str`）；`[at:+123]` 在插件侧直接降级为纯文本 `@+123`；转义写法 `\[at:123\]` 交付时会丢掉 `[` 前的反斜杠（概率极小，未处理）；"意图未被满足"告警按会话去重、无容量上限。
7. **性能**：没有 profiler 基准数据，只能说未观察到数量级退化，**不承诺**零回归。
