# AtTool · AstrBot 艾特工具

AtTool 为 AstrBot 提供 QQ 群成员搜索与艾特标签渲染。模型按昵称或群名片查找成员，在回复中输出 `[at:ID]`，由插件转换为平台的 At 消息组件；普通的 `@名字` 文本本身不是艾特组件。

本仓库是 cmdst 维护的重制版，保留原作者糯米茨的署名与许可证。元数据声明支持 AstrBot `>=4.26.0`、`aiocqhttp` 平台；这是声明范围，不代表逐版兼容性验证。

### 加载与检查

通过管理界面加载插件后，核对插件详情中的版本字段和加载结果。版本字段可区分这里的 v2.5.2 与 v2.6.5，但不能区分同一版本号下的后续提交；需要精确复现时，同时记录标签或提交号。

1. 使用支持工具调用的模型，并启用插件。
2. 如果会话或人设限制工具列表，放行 `search_and_mention` 和 `select_member_by_index`。
3. 按 AstrBot 的唤醒方式发起请求，例如“帮我艾特张三，提醒他看一下公告”。
4. 在平台上确认实际效果，不只看回复中是否出现 `@名字`。

**使用前请注意：**当前会话限制存在跨组件处理缺口，不能作为硬安全隔离；只查询信息也可能因自动补插而触发艾特。审计及普通日志可能包含用户与群标识。详见[已知限制与隐私](#已知限制与隐私)。

## 工具与搜索

本插件没有单独的聊天命令，以下工具由模型调用。

| 工具 | 参数 | 用途 |
| --- | --- | --- |
| `search_and_mention` | `name: str` | 按当前群成员昵称或群名片搜索，返回成员信息、艾特标签或候选列表。 |
| `select_member_by_index` | `index: int` | 按用户确认的序号选择候选成员，序号从 1 开始。 |

搜索优先采用精确匹配；没有精确结果时，可按配置进行子串匹配。这不是拼音或语义相似度搜索。原词未命中时，再尝试配置的别名。

唯一命中返回成员；2–30 个匹配返回编号列表，超过 30 个时要求缩小关键词。候选约 120 秒内有效，按会话保存；同群并发搜索可能覆盖列表，选择前应核对候选。

结果中的“群主／管理员／成员”只是角色标注，**不是角色筛选条件**。传入“群主”不会按角色查找，除非它恰好匹配昵称、群名片或别名。普通成员搜索没有额外的管理员门槛，但受会话范围、平台能力及工具可用性限制。

| 请求示例 | 处理方式 |
| --- | --- |
| 艾特张三，提醒他上线 | 搜索成员后输出其标签。 |
| 艾特张三和李四 | 分别查找，可在同一回复中使用多个标签。 |
| 艾特张伟，搜索出现多人 | 展示候选，等待用户选择，再调用序号工具。 |
| 艾特我刚提供的 QQ 号 | 默认允许，但号码需在本轮消息中，且通过取得的群成员名单校验。 |
| 艾特全体成员，通知明天维护 | 使用 `[at:all]`，进行权限和冷却检查。 |

## 配置

在 AstrBot 插件管理面板中调整。以下为 schema 默认值，不代表已有实例保存的值。

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `permission_verification` | bool | `true` | 检查 @全体 操作者是否为群主、管理员或 AstrBot 超级管理员。 |
| `allow_direct_qq_at` | bool | `true` | 允许使用本轮消息中的 QQ 号，需通过群成员名单检查。关闭后仍保留当前发送者的受限例外。 |
| `enable_fuzzy_search` | bool | `true` | 精确匹配无结果时，允许昵称、群名片子串匹配。 |
| `session_whitelist` | list | `[]` | 设置允许会话；非空时按完整 UMO 或群号精确匹配。 |
| `session_blacklist` | list | `[]` | 设置禁止会话，判定时优先于白名单。 |
| `llm_prompt` | text | 内置艾特操作提示词 | 自定义提示词基底，包含搜索、候选确认及标签输出说明。 |
| `at_all_cooldown` | int | `60` | 同群 @全体 放行间隔，单位秒；0 表示不限制。 |
| `enable_audit_log` | bool | `true` | 保存渲染阶段的审计记录。 |
| `member_list_cache_ttl` | int | `180` | 群成员名单缓存秒数；0 表示不缓存。 |
| `member_aliases` | list | `[]` | 别名列表，例如 `["小张=张三"]`；代码也兼容字符串值字典 `{"小张":"张三"}`。 |

白名单为空表示不额外限制会话，黑名单仍参与判定。获取完整会话标识可参考 AstrBot 的会话标识功能；本插件不注册相关命令。名单的实际覆盖边界见[已知限制与隐私](#已知限制与隐私)。

保存的 `llm_prompt` 会与插件动态说明叠加。升级插件不会代替用户改写已保存的个性化提示词。清空该项不会关闭动态说明，但不等于保留完整默认提示词；修改前应备份并检查规则冲突。

插件在初始化时读取配置。保存后若行为未更新，可通过管理界面重新加载插件；人设和会话工具设置的生效方式以 AstrBot 对应设置为准。

## 标签与权限

推荐使用标准形式，下面的号码仅用于说明语法：

```text
[at:123456789]
[at:all]
```

解析也容忍部分大小写、全角冒号、空白和零宽字符变体。`[at:名字]` 不会自动按名字搜索，而会降级为文本。

成员标签接受的来源包括：

1. 同一会话、同一发起者的工具确认 ID 缓存。缓存槽位有效期约 120 秒，后续工具调用可能更新整个槽位的时间，不是逐个 ID 的固定到期时间。
2. 开启直接给号选项时，本轮用户消息中的 5–12 位 ASCII 数字，且号码在取得的群成员名单中。
3. 当前说话人的事件 ID，同时满足群聊、名单可用、发送者在名单中。这一路不受直接给号开关控制。

未通过判定的成员标签会降级为文本：

| 当前能取得的信息 | 降级文案 |
| --- | --- |
| 有合适的群名片或昵称 | `@昵称` |
| 名单可用，但没有该号 | `@号码（不在本群）` |
| 名单不可用 | `@号码` |

纯数字或含艾特标签语法的显示名不用于降级文案。“不在本群”仅反映取得的名单，受缓存与名单完整性影响，不是实时成员身份的确定证明。

@全体默认检查操作者权限，超级管理员依据 AstrBot 的 `admins_id` 配置判断，角色结果缓存约 300 秒。关闭验证仅跳过插件侧检查，不会授予机器人平台权限。冷却按群计算，从插件放行时开始；拒绝时降级为 `@全体成员` 文本，启用审计时可查原因，不保证正文自动附带原因。

## 渲染与插件共存

插件在结果装饰阶段统一转换标签。搜索唯一命中时还会保存补插记录：整轮回复既没有标签、也没有 At 组件时，主钩子可补入该成员标签。记录按会话和发起者区分，约 120 秒内有效，一次记录只保存一个目标。

事件级 `event.send`／`event.send_streaming` 包装只转换已有标签，不在这些入口补插成员。绕过事件入口的直发消息不受该包装覆盖。标签后的部分空白和空行可能被收尾逻辑合并，影响分段位置。

### splitter

既有互操作记录中，AtTool 先于当时的 splitter 进行结果装饰，由后者决定 At 归入哪一段。可检查“跟随下段”或“嵌入”等策略，并避免清理规则删除标签。

已有验证包括钩子顺序核对及按源码建模，不等于真实插件端到端验证。升级插件或宿主后，应在自己的环境复测分段与艾特效果。

### meme_manager 的历史冲突

曾复现 meme_manager 在正文处理阶段删除方括号标签：当 `generation.markup.enable_alternative` 与 `generation.markup.remove_invalid_alternative` 同时开启，并满足其作用域条件时，艾特标签可能被当作无效表情标记删除。

若模型输出标签而最终消息缺失，可核对上述设置。关闭删除无效替代标记，或关闭替代标记功能，是当时的处理方式。此记录解释历史冲突，不表示所有版本都存在问题，也不说明当前环境的配置状态；升级后应重新核对。

## 排障

| 现象 | 优先检查 |
| --- | --- |
| 模型不调用工具 | 模型的工具调用能力、人设或会话工具列表、插件启用范围；留意工具缺席或意图未满足告警。 |
| 搜不到人 | 实际昵称、群名片、匹配设置、别名及成员接口；角色标注不提供角色检索。 |
| 只出现 `@号码` 文本 | 可信来源与成员名单告警，不把文本当作真实艾特。 |
| 标签消失或原样出现 | 模型输出、上游正文清理、表情插件、分段及流式处理。 |
| 有放行记录但消息未到达 | 平台发送结果。历史上曾出现 `retcode=1200 Get Uid Error` 拒收整条消息。 |
| 名单可能过期 | 搜索与渲染共享缓存，再搜一次不保证强制刷新；缓存到期后的拉取也可能失败或不完整。 |
| 修改后未生效 | 核对插件加载记录并实际验证，不仅凭进程启动时间和文件修改时间判断加载版本。 |

审计默认按日保存在 AstrBot 插件数据目录的 `astrbot_plugin_AtTool/audit/at_audit_YYYYMMDD.jsonl`。字段为 `time`、`group_id`、`operator_id`、`op_type`、`target_id`、`allowed`、`reason`。

审计表示渲染阶段的判定，不是平台投递成功。跨组件恢复还存在审计缺口；没有记录不能单独证明没有艾特，出现告警也不能只归因于模型没有调用工具。

## 已知限制与隐私

### 艾特行为与会话限制

- **纯查询仍可能触发艾特。** 唯一搜索命中会建立补插记录，随后无标签回复可能自动补入成员标签；当前没有独立的只查询模式。序号选择不建立同样的补插记录，不能据此保证所有查询均无提醒。
- **会话限制不是硬安全隔离。** 跨组件恢复先于会话准入执行，存在可信成员标签绕过限制的静态代码路径；尚未完成真机验证。不要仅依赖黑白名单隔离敏感会话。
- 候选列表按会话共享，同群并发搜索可能覆盖或误用候选；不要把它与按发起者隔离的可信 ID、补插缓存混为一谈。
- 群成员可以自行修改昵称和名片，这些内容可能包含诱导模型的文字，不应作为可信指令。

### 兼容性与其他限制

- 名单缓存可能导致误降级或使用过期目标；工具确认 ID 不做成员身份二次校验，仍可能被平台拒收。权限结果也有缓存，角色变更不一定立即生效。
- 标签策略不统一拦截其他插件直接构造的 At。上游删标签、提前清空结果链、绕过事件入口直发，或包装器异常回退时，插件不能保证覆盖。
- 提示词不能保证模型每次正确调用工具；流式回复不跨 chunk 拼接残缺标签。工具状态消息场景和真实跨插件端到端效果仍需复测，没有性能基准保证。

### 日志与隐私

- 审计与普通日志可能包含群号、QQ 号、昵称、搜索词和会话标识。关闭审计不等于普通日志停止记录这些内容。请限制访问并自行安排保留清理；目前无自动清理策略，审计写盘失败仅告警。
